# Диск · локальный прокси

Локальная панель для диагностики загрузок **Яндекс Диска 4 на Windows**. Показывает реальные ошибки HTTP 500, состояние каждого файла и число новых загрузок, подтверждённых Windows. Может временно откладывать полностью облачные файлы с ошибкой, чтобы приложение получало возможность обрабатывать оставшуюся очередь.

**Статус: экспериментальная версия 0.1.** Прокси не восстанавливает недоступные данные на серверах Яндекса и не гарантирует ускорение синхронизации. Файл с ошибкой остаётся незагруженным. Работа с другими версиями клиента требует проверки.

## Быстрый запуск

1. Установите [Python 3.12 для Windows](https://www.python.org/downloads/windows/). Нужен Python Launcher (`py`). Права администратора для самого проекта не требуются.
2. Скачайте исходники или клонируйте репозиторий в отдельную папку. Не размещайте проект внутри синхронизируемой папки Яндекс Диска.
3. Запустите **Start.cmd**. При первом запуске создаётся `.venv` и устанавливается mitmproxy из PyPI. Нужен доступ в интернет.
4. В браузере откроется **http://127.0.0.1:18765**. Если пути не определились автоматически, нажмите **«Настройка»** и укажите папку синхронизации и установленный `YandexDisk4.exe`.
5. Нажмите **«Запустить MITM»**, прочитайте описание изменения доверия HTTPS и подтвердите использование сертификата. Windows может показать собственное окно подтверждения.

Командная строка остаётся видимой. В ней работают сервер панели и помощник восстановления. Вкладку браузера можно закрывать и открывать снова. **Не закрывайте окно CMD, если хотите оставить прокси включённым.**

Python 3.13 можно использовать командой `py -3.13 bootstrap.py`; основной проверенный вариант — Python 3.12. Проверено с клиентом Яндекс Диска 4.28.6.5804 на Windows 11. Linux, macOS, Диск 3 и несколько аккаунтов одновременно не поддерживаются.

## Что видно в панели

- **Ещё не на ПК** — оставшиеся файлы, отмеченные «Хранить на компьютере».
- **Новые загрузки** — полностью сохранённые файлы с начала наблюдения. Счётчик и объём сохраняются при перезапуске. Файлы, уже находившиеся на ПК при первом запуске, сюда не входят.
- **На компьютере** — все локальные файлы из отслеживаемого списка, включая ранее скачанные.
- **Ответы 500** — настоящие ответы сервера за текущий запуск панели. Получение ссылки с HTTP 200 не означает успешную загрузку содержимого.
- **Передано по сети** — байты распознанных потоков, включая повторы и диапазоны. Это не общий объём сохранённых файлов; часть потоков может не сопоставиться с именем.
- В карточке файла отдельно показаны HTTP запроса ссылки, HTTP содержимого и подтверждённый Windows объём. Для новых файлов указано, был ли прокси включён в момент завершения.

## Режимы обработки ошибки 500

| Режим | Поведение |
| --- | --- |
| Отложить файл через Windows | После первого HTTP 500 временно меняет локальную отметку только у полностью облачного, синхронизированного и неизменённого файла. Повторные распознанные запросы получают локальный HTTP 503 с `Retry-After`. |
| Только ограничить повторы | Возвращает временный HTTP 503 в течение паузы; отметки хранения не меняются. |
| Наблюдать | Собирает события, пропускает ответы без изменения и не меняет отметки хранения. |

По умолчанию используется откладывание. Частично скачанные, изменённые и несинхронизированные файлы автоматически не откладываются. Если Windows не разрешает безопасное изменение отметки, файл остаётся в исходном состоянии. Кнопка **«Повторить»** возвращает отложенный файл в очередь.

Решение о порядке загрузок принимает приложение Яндекс Диска. Успешное откладывание само по себе не доказывает, что другие файлы скачиваются: для этого есть отдельный счётчик новых загрузок.

## Включение, остановка и восстановление

**Таймера и автоматического отключения через час нет.** Пользователь включает и выключает прокси сам. При обычной остановке:

1. завершается клиент с прокси и сам прокси;
2. удаляется корневой сертификат именно этого локального сеанса;
3. восстанавливаются исходные отметки хранения с проверкой идентификаторов файлов;
4. Яндекс Диск запускается с прямым подключением.

Остановить можно кнопкой **«Остановить и восстановить»**, файлом **Stop.cmd** или `Ctrl+C` в основном окне CMD. Закрытие CMD и сбой прокси также запускают восстановление отдельным помощником. После аварийного выключения ПК, принудительного завершения всех процессов или ошибки восстановления запустите **Recover.cmd**. При следующем запуске панель также проверяет незавершённые сеансы.

**Сохраните `.local`, пока восстановление не завершено.** В ней находятся исходные отметки хранения и данные для удаления сертификата. Не удаляйте эту папку во время работы. Если отметки не удалось вернуть, в панели будет «Нужно завершить восстановление».

Автозапуска при входе в Windows нет. Режим обработки и ручное состояние сохраняются локально; обычная ручная остановка оставляет прокси выключенным.

## HTTPS и локальные данные

При первой настройке создаётся отдельный сертификат для этого ПК. Его закрытый ключ хранится **только в `.local/certificates`**. Перед включением панель показывает отпечаток. Доверие добавляется в `CurrentUser\Root`, не в хранилище всего компьютера. Пока сертификат установлен, это влияет на доверие HTTPS приложений текущего пользователя — не только Яндекс Диска.

Системный прокси Windows не меняется. Адрес прокси передаётся только запускаемому процессу Диска через переменные окружения. Сервер слушает `127.0.0.1:18765`, прокси — `127.0.0.1:18080`. Расшифровка ограничена доменами выдачи файлов Яндекс Диска. Проверка сертификатов серверов Яндекса остаётся включённой.

Новый OAuth, пароль или токен доступа не нужны: используется уже авторизованное приложение. Облачные файлы не удаляются и не переименовываются. Успешные ответы и содержимое файлов не подделываются.

В `.local` остаются **пути и имена файлов**, времена событий, коды ответов, идентификаторы файлов Windows и журнал восстановления. Содержимое файлов, cookies, заголовки авторизации и полные подписанные ссылки не записываются. Не отправляйте `.local` другим пользователям и не добавляйте её в Git. Встроенная телеметрия и отправка журналов отсутствуют.

## Если что-то не работает

- **Ошибка 500 сохраняется:** это ответ сервера; проверьте доступность файла через обычный браузер. Прокси не может восстановить серверную копию.
- **TLS отклонён:** проверьте подтверждение сертификата Windows. Не отключайте проверку сертификатов серверов. Остановите сеанс и попробуйте снова.
- **Не найдено приложение:** укажите путь к установленному `YandexDisk4.exe` в настройке. Для другой версии клиента совместимость не обещается.
- **Нет файлов в очереди:** проверьте выбранную папку и отметку «Хранить на компьютере». Для обычных файлов без Cloud Files API возможности откладывания нет.
- **Порт занят:** завершите другую копию панели или другое приложение на портах 18765/18080. Не запускайте две копии из разных папок одновременно.
- **Нужно завершить восстановление:** используйте Recover.cmd и сохраните локальный журнал. Удаление исходной папки или замена файла может помешать возврату отметки по прежнему идентификатору.

## Разработка

```powershell
py -3.12 bootstrap.py --no-mitm
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Структура: `server.py` — локальный API и учёт файлов; `session.py` — сеанс и восстановление; `winops.py` — Cloud Files и процессы Windows; `addon.py` — наблюдение HTTP; `downloads.py` — устойчивый счётчик завершений; `settings.py` — локальные пути; `dist/` — интерфейс без сборки и внешних ресурсов.

Основные механизмы описаны в документации [mitmproxy](https://docs.mitmproxy.org/stable/concepts/certificates/), [CfGetPlaceholderInfo](https://learn.microsoft.com/en-us/windows/win32/api/cfapi/nf-cfapi-cfgetplaceholderinfo) и [CfSetPinState](https://learn.microsoft.com/en-us/windows/win32/api/cfapi/nf-cfapi-cfsetpinstate).

Это независимый инструмент, не официальный продукт Яндекса.
